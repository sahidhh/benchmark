## Root Cause Analysis

There are **two distinct bugs**, both originating in `OrderRepository.cs`.

---

### Bug 1 — Quantities Always Calculated as 1

**File:** `OrderRepository.cs`
**Lines:** 28–29 (INSERT) and 44–48 (SELECT reconstruction)

**Evidence:**

In `InsertOrderAsync`, the items blob is built as:
```cs
// Line 28-29
var itemsBlob = string.Join(",", order.Items.Select(i => i.ProductId));
```

Only `ProductId` values are serialized — `Quantity` is **never written to the database**. The column comment even confirms this: `// Items stored as comma-separated product IDs — quantities not persisted`.

When the order is later read back in `GetOrderAsync`, the blob is deserialized as:
```cs
// Lines 44-48
var items = itemsBlob.Split(',').Select(id => new OrderItem
{
    ProductId = int.Parse(id),
    Quantity = 1,   // ← hardcoded; no quantity was stored to recover
}).ToList();
```

Because quantity was never persisted, every `OrderItem` is reconstructed with `Quantity = 1` regardless of what the customer actually ordered.

---

### Bug 2 — Order Total Changes Over Time

**File:** `OrderRepository.cs`
**Lines:** 55–61

**Evidence:**

```cs
public async Task<decimal> GetProductPriceAsync(int productId)
{
    // fetches CURRENT price — not the price at order time
    var cmd = new SqlCommand(
        "SELECT price FROM products WHERE id = @id", conn);
```

The price lookup queries the **live `products` table** with no timestamp or snapshot. If a product's price changes after an order is placed, every subsequent call to `CalculateTotalAsync` will return a different total, because it recalculates using whatever the price is *right now*.

### Investigation

*   **`OrderController.cs`**: The `GetTotal` endpoint calls `_orderService.CalculateTotalAsync(orderId)`.
*   **`OrderService.cs`**: `CalculateTotalAsync` retrieves the `order` from `_repo.GetOrderAsync(orderId)`. **Finding for "Order total changes over time":**
The system fetches the current product price from the `products` table when calculating the total, rather than using the price at the time the order was placed. If product prices change in the `products` table, the order total will change accordingly.

**Exact file and line where the bug originates (for changing total):**
`OrderRepository.cs`, line 60: `SELECT price FROM products WHERE id = @id`

**2. Quantities are always calculated as 1:**

*   **`OrderService.cs`**: `PlaceOrderAsync` creates an `Order` object with the provided `items` and then calls `_repo.InsertOrderAsync(order)`.
*   **`OrderRepository.cs`**:
    *   `InsertOrderAsync(Order order)`: The line `var itemsBlob = string.Join(",", order.Items.Select(i => i.ProductId));` serializes only the `ProductId` into a comma-separated string. **Finding for "Quantities are always calculated as 1":**
The `OrderRepository` only stores the `ProductId` for each item in an order, not the `Quantity`. When an order is retrieved, the `Quantity` is hardcoded to `1` during reconstruction, leading to incorrect total calculations.

**Exact file and line where the bug originates (for quantities always 1):**
